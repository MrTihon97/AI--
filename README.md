# AI-тренажёр для менеджеров по продажам (MVP)

Тренажёр для отделов продаж: ИИ (без реальной нейросети) играет роль клиента — строгого управляющего **Артёма** или главврача **Марины**. Менеджер тренирует звонок по продаже медицинской CRM, получает разбор ошибок и ведёт прогресс по плану обучения.

Всё работает **в браузере**: Smart Mock API + правила + `localStorage`. Бэкенда и настоящих LLM-вызовов нет — интерфейс при этом ощущается как живой продукт.

**Демо:** https://ai-zeta-brown-50.vercel.app/  
**Репозиторий:** https://github.com/MrTihon97/AI--

## Три экрана (сценарий ТЗ)

### 1. Главный экран (дашборд)
Личный прогресс, навыки по 5 этапам продаж (красная / жёлтая / зелёная зона), стрик, план на сегодня, история ролёвок, график динамики балла.

### 2. Ролёвка (окно «звонка»)
Выбор клиента → карточка (сегмент, боли, цели) → чат.  
Клиент не отвечает мгновенно: «печатает…», «внимательно читает…», задержка по сложности хода, **пословный стриминг** текста.  
Внизу — чипы-подсказки по текущему этапу (тезис на кнопке, полный шаблон в поле; на контакте — `[Ваше имя]` / `[Название CRM]`).  
На телефоне: чат на весь экран, высота под `visualViewport` / клавиатуру, `safe-area`, бургер-меню.

### 3. Разбор
Оценки **1–10** по этапам, ошибки с **реальными цитатами** из вашего чата, 2–3 рекомендации, вердикт «Пройдено» / «Требуется пересдача».  
Цитата на карточке привязана к **этапу FSM** реплики (с fallback для closing, если Zoom ушёл в stamp предыдущего этапа).  
После разбора сессия **сохраняется в историю** (`sessionId` — без лимита на число ролёвок; «3/3» в плане — только чеклист).

### Прогон за 90 секунд
1. Дашборд → план / навыки.  
2. «Начать ролёвку» → Марина или Артём → карточка → чат.  
3. Представиться → боль (потери заявок) → ценность → слот **завтра в 14:00**.  
4. Завершить → разбор → на главную → стрик/история.

Опционально в скринкасте: 2× мат → бан этики; 3× оффтоп → клиент бросает трубку.

## Как чат «притворяется» умным без нейросети

Линейный сценарий «реплика 1 → 2 → 3» ломается на первой свободной фразе. Поэтому стоит **Smart Mock**: NLU + FSM этапов + сборка ответа из битов (Ack / Fact / Ask), а не random из огромного банка.

### Дисциплина звонка (глобальные правила)
Одинаково для Марины, Артёма и любой новой персоны:

| Правило | Поведение |
|---------|-----------|
| **Этика (мат)** | 1-е → предупреждение; 2-е → бан сессии, ввод lock, «Задание провалено» |
| **Оффтоп** | 3 подряд вне темы продаж → клиент завершает разговор |
| **Знакомство** | **Absolute intro-gate:** без имени/компании любой probe («Сколько кресел?») → pushback «а мы знакомы?»; price/CRM/Zoom-keywords игнорируются; FSM остаётся на `intro` |
| **Ack на intro** | После представления клиент сначала узнаёт имя/компанию; deep-статы — только после `introAcknowledged` |
| **Закрытие** | «Спишемся когда-нибудь» не считается; нужен **день + время**; soft WhatsApp → `need_slot` |

```
сообщение → этика (2) → оффтоп (3) → логика персонажа
```

### Эволюция решения

| Этап | Что сделали | Зачем |
|------|-------------|--------|
| 1. Банк фраз | Большие пулы + overlays | Быстрый старт «говорит по-русски» |
| 2. NLU + FSM | Интент + этап/настроение | Понимание контекста воронки |
| 3. Beats + слоты | Сборка хода | Логичность вместо random-цитаты |
| 4. 4 механики | Emotion / Listening / Pacing / Timing | Живость без LLM |
| 5. Гварды + правила | Этика, оффтоп, intro, слот | Учит дисциплине звонка |
| 6. Mirroring + keywords | Имя/компания в Ack, hot-слова → слот | Ответ цепляется за ввод менеджера |
| 7. Динамический разбор | Rule-based scorer + цитаты | Плюс к критерию ТЗ |
| 8. Stage-stamped quotes | Этап FSM на реплике → карточка | Без cross-stage contamination |
| 9. Absolute intro-gate | Gate до nonsense; keywords off | Нельзя обойти представление |
| 10. Closing quote fallback | Zoom/время → closing даже при stamp objection | Нет пустого placeholder на слоте |
| 11. Presentation soft-match | Ценность в любом stamp / прыжок к слоту | Нет ложного «нет реплик» на презентации |
| 12. Legacy МИС + value metrics | 1С/Инфодент: замена≠штраф, интеграция=успех; HQ = метрики+цифры | Возражения и экономика без «воды» |

**Честно про банк:** большой банк — след быстрого старта. В рабочем ходе важнее **логика сборки**, а не размер пула. Целые фразы остались как fallback.

### Четыре механики реализма
1. **Emotion Inertia** — раздражение копится и медленно остывает.  
2. **Active Listening** — клиент цепляется за CRM / потери / WhatsApp / цену.  
3. **Pacing** — 2+ монолога без вопроса → перебивает.  
4. **Timing** — простой ход ~1 с, сложный аргумент 2.5–3 с + «читает…».

Плюс род голоса: Артём не говорит «поняла» (`fillGender` / `enforceVoiceGender`).

### Контекст в ответе (без LLM)
Клиент не сыпет статичный шаблон — подмешивает то, что сказал менеджер:

| Механика | Что делает |
|----------|------------|
| **Name / company mirroring** | «Это Тихон, ДентаCRM» → Ack вроде «А, Тихон, понял вас…» / «Ок, ДентаCRM…»; имя живёт в слотах сессии |
| **Keyword → слот** | Hot-слова `цена` / `дорого` / `whatsapp` / `excel` / `crm` выбирают matching Fact (**только после представления**) |
| **Smooth intro guard** | Пока нет `introAcknowledged` — без прыжка в глубокие discovery-статы |
| **Absolute intro-gate** | Без ID любой бизнес-вопрос → `contact_gate` (даже если NLU видит «цену» / nonsense по редкому слову) |

Сборка: `composeBeat.ts` + `personaSlots.hotKeywordTopic` + `beats.needsContactGate` + слоты FSM.

### Цитаты в разборе (FSM stamp)
Раньше evaluator сканировал весь чат regex’ами и мог повесить Zoom на «контакт» или питч на «закрытие». Сейчас:

| Шаг | Что происходит |
|-----|----------------|
| **Отправка** | В `ChatMessage` / `intentLog`: `{ text, stage, intent, timestamp }` |
| **Маппинг** | `intro→contact`, `discovery→discovery`, `presentation→presentation`, `objection→objections`, `closing→closing` |
| **Re-stamp closing** | Если ход закрыл сделку (Zoom / день+время / `SESSION_COMPLETE`) — реплика помечается `CLOSING`, даже если send-time был `objection` |
| **Карточка** | Цитата из реплик этого этапа |
| **Closing fallback** | Нет stamp `closing` → последняя реплика с Zoom / временем / «завтра» / слотом (`quotesForClosingWithFallback`) |
| **Presentation soft-match** | Ценность продукта (дашборд / автодожим / модули / интеграция) в любом stamp → этап засчитан; placeholder «нет реплик» запрещён (`quotesForPresentationWithFallback`) |
| **Прыжок к слоту** | Клиент сразу к Next Step при живой discovery — без ложного штрафа за «пустую» презентацию |
| **Legacy МИС** | Замена 1С/Инфодент → штраф objections; интеграция/модуль → успех (`intents.ts`) |
| **HQ value** | `evaluateValuePitch`: кресла/удержание + цифры; абстрактная «выгода» без метрик — штраф presentation |
| **Пустой этап** | Placeholder без чужой цитаты (для closing/presentation — только если ценности/слота реально не было) |
| **realign** | Дедуп + этика + sanitize justification — **без** keyword-remap между этапами |

Код: `Roleplay.tsx` (stamp) → `feedbackEngine.ts` → `reportValidator.ts`.

### Возражение «у нас уже есть 1С / Инфодент» + экономика питча
Клиники **не меняют** рабочую МИС «в лоб». Тренажёр это проверяет и в диалоге, и в разборе:

| Сигнал менеджера | Детектор | Реакция клиента | Разбор |
|------------------|----------|-----------------|--------|
| «Заменим вашу 1С», «перейдите вместо вашей МИС» | `full_replacement_pitch` | Жёсткий pushback (риск базы, простой) | Штраф этапа **возражения** |
| «Интеграция», «модуль поверх 1С», «в связке» | `integration_pitch` | Ок, но просит цифры окупаемости | Успех **возражений** |
| Упоминание 1С / Инфодент / MedDesk / … | `legacy_crm` | Клиент сам озвучивает «у нас уже есть МИС» | Слот `legacyCrmRaised` |
| Вопрос про МИС на **discovery** | `legacy_crm_discovery` | Явно называет стек (1С:Медицина) + «поверх или перенос?» | Disclosure, не objection-push |

**Качественная экономика** (`evaluateValuePitch` → `isHighQualityValue`) засчитывается только при связке:
1. метрика стоматологии — загрузка/простой кресел **или** возврат/отвал/неявки/повторные визиты;  
2. конкретные цифры — `%` / `₽` / дни / часы.

Абстрактное «вам будет выгоднее и удобнее» без метрик и цифр → штраф **презентации**.

Файлы: `intents.ts`, `valueMetrics.ts`, слоты в `personaSlots.ts`, ветки beats `legacy_*`, оценка в `feedbackEngine.ts`.

### Mobile
- `viewport-fit=cover`, `interactive-widget=resizes-content`  
- Чат full-screen на телефоне, высота через `visualViewport` (клавиатура)  
- `safe-area-inset-bottom`, textarea `text-base` (без zoom iOS)  
- Чипы с wrap, sticky CTA на дашборде, бургер-меню, bottom-sheet модалки  

### История и план
- Лимита на число ролёвок **нет**  
- «План на сегодня 3/3» — чеклист, не квота  
- Сохранение при открытии разбора; у сессии уникальный `sessionId` (похожие баллы/цитаты не схлопываются)

## Технологии

- **Фронт:** React, Vite, TypeScript, Tailwind CSS  
- **Бэкенда нет:** Smart Mock в `src/services/api.ts`, сценарии/слоты в коде, прогресс в `localStorage`  
- UI не читает JSON напрямую — подмена на реальный бэк = одна точка `getSmartReply`

Ключевые файлы:

```
src/services/api.ts              → контракт UI + saveRoleplayResult (история)
src/services/roleplayApi.ts      → глобальные гварды (этика → оффтоп → персона)
src/services/feedbackEngine.ts   → разбор, stage-stamp, closing/presentation fallback, МИС/HQ value
src/utils/reportValidator.ts     → дедуп / этика (без post-hoc remap этапов)
src/dialogue/engine.ts           → оркестратор; nonsense не бьёт intro-gate
src/dialogue/beats.ts            → absolute needsContactGate + ветки legacy_*
src/dialogue/composeBeat.ts      → Ack/Fact/Ask + mirroring; keywords только после intro
src/dialogue/personaSlots.ts     → банк слотов + реакции на 1С/Инфодент
src/dialogue/intents.ts          → legacy_crm / replacement / integration
src/dialogue/valueMetrics.ts     → evaluateValuePitch (кресла + цифры)
src/pages/Roleplay.tsx           → чат, stamp, mobile viewport, sessionId
src/pages/Feedback.tsx           → разбор + автосохранение в историю
src/data/mock-data.json          → профиль, клиенты, история, план
```

## Что сделано

### Обязательное ТЗ
- 3 экрана + E2E-петля (прогресс → ролёвка → разбор → стрик/история)  
- Моки отделены api-слоем, скелетоны загрузки  
- Живой чат: задержки, «печатает…»  
- Разбор 1–10, цитаты, рекомендации  
- План на сегодня, зоны навыков, график  

### Бонусы и усиления
- Стриминг ответа, 2 сегмента клиентов, **mobile** (viewport / safe-area / sticky CTA)  
- NLU + FSM + beats + 4 механики  
- Гварды этики/оффтопа, **absolute intro-gate**, жёсткий closing (день+время)  
- **Mirroring:** имя/компания в Ack; hot-keywords → Fact только после представления  
- **Stage-stamped quotes** + **closing / presentation soft fallback** (Zoom и ценность не теряются в placeholder)  
- **Legacy МИС:** замена 1С/Инфодент = ошибка; интеграция/модуль = успех (диалог + разбор)  
- **HQ value-pitch:** засчитывается экономика только с метриками клиники + цифрами; «вода» штрафуется  
- История без лимита; `sessionId` на сохранение; план 3/3 ≠ квота  
- Динамический evaluator, stage-chips с плейсхолдерами, gender-safe голос  
- Smoke: `test:intents` / `test:dialogue` / `test:report` (в т.ч. МИС / abstract benefit)

## Что осознанно вырезано

| Вырезано | Почему |
|----------|--------|
| Реальные LLM / бэк / БД | Условие ТЗ |
| База знаний | Вне скоупа («готовая база приложена») |
| Auth, оплаты, голос | Не нужны для E2E |
| Дашборд РОПа | Выбрали стриминг + 2-й клиент + глубину диалога |
| Очередь реплик «1→2→3» | Ломается на свободном вводе |
| E2E автотесты | В ТЗ «не нужно»; есть smoke |
| Банк как главный движок | Рабочая модель — сборка хода |

## Тайминг (честно)

Суммарно **~8–10 часов** работы с ИИ в несколько итераций.

| Блок | ~часы | Фокус |
|------|-------|--------|
| Каркас + моки + api + 3 экрана | 2–2.5 | кликабельная E2E-петля |
| Банк / персоны / интенты | 1.5–2 | «говорит по-русски» |
| NLU + FSM + beats + механики | 2–2.5 | логичность без LLM |
| Гварды, intro/closing, mirroring, цитаты разбора | 2–2.5 | дисциплина + живой контекст + честный фидбек |
| Legacy МИС + HQ value + soft presentation | 0.5–1 | возражения по стеку и экономика без «воды» |
| UI, mobile, чипы, стриминг, сдача | 1–1.5 | живость + деплой / README |

Приоритет: **сначала петля end-to-end**, потом живость чата и разбора, потом визуал.  
Не успеть «идеальный ИИ» — нормально; важнее работающий тренажёр и понятное мышление, почему диалог устроен так.
